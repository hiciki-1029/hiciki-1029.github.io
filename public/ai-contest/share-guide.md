# AI创作大赛，我是怎么组织的

Ciki

## 这场分享希望帮助大家做什么

在公司里组织一场AI大赛，需要处理很多具体问题：怎样找到大家愿意参与的任务，谁提供工具与时间支持，如何评价不同类型的作品，以及比赛结束后谁继续跟进。

这次想结合某游戏公司2025、2026年校招生培养项目中的AI实践，和大家讨论组织比赛时遇到的几个问题，以及我们当时为什么这样安排。各公司的业务、人群和资源条件不同，希望这些实践能为大家提供一些参考。

网页适合现场展示，文档用于备讲和会后阅读。这份版本以经验分享为主，配套资料供会后筹备时参考；正式时长以活动安排为准。

## 规划时，我在考虑什么

这场比赛，组织的期待是什么？可以先讨论普及体验、业务应用、新人培养与交流三类期待，明确本轮重点，再安排任务、支持与评价。

规划AI创作大赛时，我会进一步想，我们组织可能希望让大家实际应用AI、尝试解决工作问题、促进新人交流、了解新人和他们的想法，以及积累案例和方法。这几个方向是规划时的考虑，实际安排仍需要结合这次的重点。

为什么这样想？本轮面对的是游戏公司的校招生，很多新人已经使用AI，也有岗位实习经历。他们需要实际应用的机会，也需要认识不同岗位的同届伙伴。因此这一轮更关注新人交流、AI应用与学习，以及留下可复用的实践。再回看2025年的共同游戏任务与2026年的开放选题，可以理解培养需要怎样影响比赛安排。

## 为什么两年的任务不一样

2025年，我们在校招生培养项目里，安排了一项共同任务：用AI制作小游戏，并发布到游戏平台。方案按约4人一组设计，每组配置一位有技术开发背景的同学，成员可以尝试策划、开发、美术、测试、运营宣发等角色。

结合游戏公司的业务，以及游戏平台提供的发布和体验条件，我们希望新人通过不同角色的协作，了解游戏创作、发布和玩家反馈的过程。最后产出了6款小游戏，其中3款进入游戏平台游戏新人榜，最好成绩到第6名。年度总结记录，截至2025年10月，累计游玩71,590，累计评论206条。游玩量是累计记录，不能直接理解为去重玩家人数。

2026年，我们把作品方向扩展到业务与个人提效、创意表达。32位来自20个部门的新人，在21天创作期内完成了24件作品。作品可以从各自的工作问题或创作兴趣出发，先完成可以展示、可以体验的版本。

结合两年的培养需求，任务安排也有所调整。共同做游戏，希望帮助新人了解业务和不同角色的协作；开放选题，则希望让不同岗位的新人从自己的工作问题或创作兴趣出发，尝试把想法做出来。

## 选择一 为什么办

### 结合业务和人的情况，先明确目的

在设计比赛之前，可以先看看业务当下需要解决什么问题，参与者的AI基础和工作情况怎么样。结合这些情况，再确定这次更希望帮助大家开始尝试、解决具体问题，还是通过实践促进协作，更多地了解参与者。

这些目标可以兼顾，但在分配时间、支持和评价权重时，需要排顺序。如果主要目标是普及体验，就应优先降低起步难度，提供基础支持；如果主要目标是业务应用，就需要提前找到愿意试用的人，并明确怎样判断问题是否改善。

| 主要目标 | 希望看到的变化 | 优先安排 |
|---|---|---|
| 普及体验 | 更多员工愿意开始实践 | 简单任务、可用工具、基础练习 |
| 业务应用 | 具体工作问题有了可验证的解法 | 场景负责人、试用条件、效果记录 |
| 新人培养与交流 | 在真实任务中练习协作，获得反馈 | 角色分工、过程记录、交流机会 |

### 结合这一届新人的情况，我们怎样安排

2026年规划项目时，我最初也考虑增加AI工具课。但内部调研显示，很多新人已经在使用AI，入职前也有一段实习经历，对自己的岗位并不陌生。结合这些情况，我们希望给大家更多在实际任务中应用AI的机会，也通过作品交流，让不同岗位的新人彼此了解。

因此，这一轮的分享重点放在任务、作品与反馈上。这是结合本届参与者基础作出的选择。面对基础较弱的群体，短练习、示范和集中答疑仍可能很有必要。

筹备时可以先写清：“我们最希望____这群人，在比赛后发生____变化。”再用任务、支持和评价检验是否一致。筹备时可以用这句话，检查任务、支持和评价是否与目的相符。

## 选择二 任务怎么设计

### 把比赛任务说明白

有了比赛目的，还需要把任务说明写具体。参与者需要知道为谁解决什么问题、最后作品要求、AI参与哪个环节、什么时候交，以及遇到问题可以找谁，才比较容易开始行动。

2025年，我们把发布到游戏平台写进任务，让作品面对真实平台和玩家。2026年，把可演示、可体验作为基本交付要求，有条件的作品再继续尝试上线。任务范围改变，完成标准也应随之调整。

今年活动网页面向本届校招生，支持个人或2—3人组队，设置“整体提效”和“脑洞创新”两条赛道。前者包括真实业务问题和可复用的个人工作流，后者包括游戏、新玩法、互动体验和AIGC应用。创作期21天、工具不限，交付项目说明和可演示原型，活动网页要求5分钟作品介绍与答辩，实际决赛按每组8分钟安排。项目说明可以补充AI参与过程、收到的反馈和当前限制，帮助评委理解作品。

### 结合任务，安排组队方式

2025年的共同任务涉及小游戏的多个角色，方案安排了技术同学与其他角色一起参与；2026年则让大家围绕问题自主寻找伙伴。

其他公司可以先看任务需要什么能力，再决定哪些能力需要在小组内具备，哪些可以通过答疑或外部支持获得。组队以后，也要明确每个人的贡献与责任，避免团队作品最后只由一个人推进。

## 选择三 如何支持

### 组织比赛，需要哪些资源支持

这一轮由我负责统筹，学员运营、场地物料、摄影和IT设备等环节有跨团队同事支持，业务评委也投入了审阅和讨论时间。所以筹备时，需要先想清楚有哪些人可以支持，再和相关方沟通负责什么、需要投入多少时间。

| 资源或角色 | 启动前至少明确什么 |
|---|---|
| 项目负责人 | 谁负责目标、规则、节奏与异常处理 |
| 业务伙伴与试用者 | 哪些问题值得做，作品完成后谁愿意试 |
| 工具与技术支持 | 账号、费用、使用条件与答疑入口 |
| 参与者的leader与参与者 | 参加的意义、投入时间、分工，以及业务安排有冲突时怎样协调 |
| 资料使用咨询入口 | 什么资料可以用，什么需要脱敏，拿不准时问谁 |
| 评委 | 评价标准、材料形式、工作量与截止时间 |
| 活动与后续支持 | 场地设备、展示安排、试用与维护负责人 |

预算也应分开看：奖金、物料和茶歇是直接支出，员工创作、组织协调、评委审阅与后续维护都包含时间投入。各公司的既有工具与支持条件不同，不宜直接照搬一组费用。

### 了解参与者的顾虑和困难

员工是否参与，取决于很多具体条件。组织者可以从四句话入手：“这跟我有什么关系”“不知道从哪里开始”“有想法但没有时间”“做了一半卡住了”。

第一句话需要把参与动机说具体，让员工从熟悉的问题或兴趣中找到入口。第二句话需要场景示例、工具说明和必要练习。第三句话需要和主管、参与者讨论时间，把作品范围控制在可投入条件内。第四句话需要有人答疑，并在过程中提供及时反馈。

启动前还需要和提供支持的同事确认，各自负责什么，参与者遇到问题时通过什么方式联系，后续能否及时得到回应。

### 非脱产参赛，怎么和leader、参与者沟通

非脱产参赛也需要投入时间。筹备时，先明确希望参与者的leader提供什么支持，再结合实际情况沟通时间和安排。

和leader沟通时，需要说明比赛目的、创作安排和作品要求，也了解当前业务的节奏。如果时间有冲突，可以一起讨论怎样调整安排，或把作品范围收小。仅仅让leader知道有这个活动，还不足以判断参与者是否有时间完成。

和参与者沟通时，需要了解他们想做什么、有哪些工具基础、可以投入多少时间，以及目前的顾虑；同时说明作品要求、重要节点和答疑联系人。创作中遇到困难，也需要及时沟通，判断是补充支持还是调整作品范围。这些是筹备和执行时需要考虑的安排。

2026年的创作安排是第一周找问题、自主组队，接下来两周完成可演示作品。21天指创作期，之后还有公开体验、评审与路演。中途可以看一次最小可演示版本，及时了解进展和困难。

如果需要调整统一截止时间，应了解原因、向所有参赛者说明，并考虑已经按时提交的团队。

人的支持和技术准备需要同时推进，接着还要确认工具、账号和赛事平台是否可用。

### 技术资源：工具和赛事平台

赛事平台需要列入启动前的资源准备。它既服务创作者，也支持体验、评审和组织管理。本轮由Ciki用低代码工具搭建，未申请研发资源；规则设计、业务判断和跨团队支持仍由人承担。

| 使用者 | 平台要支持什么 |
|---|---|
| 参与者 | 查看规则、赛道、工具入口，报名与提交作品 |
| 体验者 | 找到作品、筛选浏览、体验、点赞与评论 |
| 初筛评委 | 独立审阅作品，填写结论与理由，意见互不可见 |
| 路演评委 | 按出场顺序查看创作者介绍、演示入口和备用视频 |
| 组织者 | 管理报名、作品、评审汇总与路演配置，并导出数据 |

下面是结合实践整理的筹备检查建议，不作为本轮全部已完成动作的记录：

- 账号与额度：谁可以使用工具、费用由谁承担，额度不足找谁。
- 角色与权限：参赛者、评委和组织者分别能看什么、能改什么。
- 关键流程：用不同角色走通报名、提交、体验和评审，检查访问条件。
- 故障与备份：明确技术联系人，准备备用演示、录屏或替代提交方式。
- 资料边界：说明资料使用范围和脱敏要求，确保演示材料可对外展示。

平台说明各角色在哪里操作；运营流程说明信息与责任怎样衔接；群内助手承接通知、答疑与查询。小规模第一轮可以用现有说明页与关联表覆盖核心流程，再决定哪些地方需要开发。

### 管理报名、作品和评审信息

报名时需要说清参与对象、选题方向和组队方式；创作中需要关联进度、答疑入口与提交材料；评审时需要收齐结论和理由，再进入合议与反馈。组织者要知道每一步由谁负责，以及信息怎样传到下一步。

2025年先用多维表格关联学员、任务进度和反馈，在节点自动提醒。2026年结合赛事入口和群内助手，支持规则说明、作品展示、答疑、通知与数据查询。节点提醒属于规则明确的流程，大赛目标、比赛规则、评审和重要取舍仍由人负责。

### 群内助手协助通知、答疑和查询

本轮AI运营助手协助答疑、通知与数据查询，学员可以在群里提问。演示页按实际功能说明整理了三个预设场景，用来介绍通知、答疑和查询的处理方式。

这些工具的价值，需要结合它们具体承担了哪些重复工作来看。对于小规模第一轮，仍然可以先用说明页和关联表把流程接起来，再决定哪里值得增加功能。

## 选择四 怎样评价

### 给未晋级的作品保留展示和交流机会

2026年的作品可以在广场被体验、点赞与评论，也安排了试玩交流；最终7件作品进入高管和业务负责人到场的精品路演。

从培养的角度，我们也需要关注没有进入路演的同学。他们同样投入了时间，可以通过作品展示和试玩交流，说明自己的想法、听到具体反馈，了解后续还可以怎样改进。路演则为部分作品提供更集中的展示和讨论机会。

准备比赛时，可以单独检查：未晋级者还能得到什么？他的作品是否仍可被体验，是否知道评价理由，是否有后续改进机会？

### 评委先独立审阅，再合议

2026年初筛由5位评委分别给出通过、待定或淘汰的意见，并说明理由。评审期间意见互不可见，合议时再讨论不同视角。

我们也希望评委写下判断理由，后续讨论时，大家能够知道不同意见从哪里来。意见不同，可能是评委拿到的信息不同，也可能是关注点不同，或者标准本身需要澄清。组织者需要把这些区别弄清楚，再形成能够解释的结论。

如果出现规则解释或调整，也需要记录并向参赛者说明，避免只有少数作品获得额外解释机会。

### 结合比赛目的，准备评审材料

备讲时可以用一个假设情境解释评价依据：作品A演示惊艳但还没有使用反馈；作品B比较朴素，却已有同事持续使用。需要进一步了解各自的问题、完成程度、AI参与和使用反馈。这是说明判断方式的假设，不对应本轮真实作品。

评价时先明确比赛目的，再了解作品解决什么问题、AI参与哪些环节、完成到什么程度，以及有哪些使用反馈。创意表达作品与业务提效作品，可以需要不同的专业视角。

对于提效作品，使用者往往能够补充很关键的信息。涉及内部系统而不便现场演示时，可以提前统一允许脱敏录屏、使用者反馈等形式，并明确怎样判断证据的完整性。

人气反馈也需要说明边界。点赞帮助作品被发现，反映关注与传播，不直接等于业务效果或质量。

## 这次比赛的成果

按项目复盘记录，32位来自20个部门的新人完成24件作品，提交率100%，无人中途退出。277名员工参与互动，留下504个赞和60条评论；5位评委给出120份独立评审意见，7件作品进入路演。作品已经完成，也收到了一些反馈；能否持续应用、实际效果如何，还需要后续跟进。

部分游戏作品已发布到游戏平台，获得玩家体验和反馈，也有作品部署为可直接体验的网页。公开评分和关注数会变化，本次分享不使用这些动态数字。

### 两个具体作品

一个需求整理工具的几位创作者来自不同业务。他们注意到需求散落在私聊、群聊和文档中，容易跟丢，于是尝试制作整理需求背景与时间节点的工具。他们希望从这个经常遇到的问题开始，尝试找到更方便的处理方式。该作品在人气奖冻结时获54个赞，9月3日复盘时为55个赞；实际节省多少时间，还需要持续使用记录。

另一个本地化支持机器人的创作者来自非技术岗位，围绕日语本地化资料与经验，制作了在工作群内响应的机器人，在实际业务群里试用并得到同事正反馈。结合这个案例，非技术岗位也可以从自己熟悉的业务问题出发参与实践，但在任务范围、工具使用和答疑上，可能需要相应的支持。

这两个案例适合帮助听众继续提问：谁需要这个作品，AI改变了什么，创作者作出了哪些判断，哪些情况仍要人工处理？演示完成、业务试用和稳定采用是不同阶段，需要分别提供证据。

## 选择五 赛后怎么跟进

### 准备继续应用的作品，由谁跟进

2025年的游戏发布到真实平台并获得玩家反馈，2026年的作品则处于演示、试用和继续打磨等不同阶段。后续跟进时，需要结合作品当前的阶段，了解它已经完成什么，还需要哪些支持。

对于准备继续推进的作品，建议赛后补一张跟进卡：谁使用、谁负责、下一步验证什么、什么时候回看。第一轮可以先选择少量有明确使用者的作品，持续记录质量、使用频率与维护投入。

### 结合参赛过程提供反馈

赛后可以和创作者讨论：为什么选择这个问题，遇到卡点尝试了什么，不同岗位如何协作，收到反馈后改了什么。已有记录支持的部分，可以进入赛后反馈交流；尚未记录的过程，需要和创作者交流补充，不能仅凭最终作品反推。团队作品也需要进一步核对每个人的具体贡献。

赛后交流可以结合选题、协作和调整过程，给创作者具体反馈；团队作品还需要核对个人贡献。

### 赛后优先跟踪三件事

后续还需要继续了解：作品是否持续被使用，参与者是否把解决问题的方法带回岗位，以及运营方式能否在下一轮稳定复用。围绕这些方向，可以分别记录使用者、频率、质量与维护，后续任务中的应用行为，以及流程运行与协调投入。这些记录问题是本次分享的整理，需要结合实际情况调整。

## 筹备时可以先讨论的问题

| 七个问题 | 第一版答案 |
|---|---|
| 我们希望改变什么 | 主要目标与准备观察的行为或结果 |
| 希望谁参与 | 人群、AI基础、参与障碍 |
| 任务怎么设计 | 问题范围、作品形式、完成标准、AI参与要求 |
| 提供什么支持 | 工具、可投入时间、答疑、中途反馈 |
| 谁负责什么 | 统筹、业务、工具支持、主管、评委 |
| 怎么评价与反馈 | 标准、接受的证据、未晋级者的反馈 |
| 赛后谁继续跟进 | 使用者、负责人、回看时间，以及后续的发展交流与经验整理 |

一句话检查：“我们让____在____创作期内，为____做出____，提供____支持，由____判断，并在赛后由____跟进。”

可以先找一个业务伙伴和几位可能的参与者，讨论这件事是否值得尝试，以及需要哪些条件，再决定第一轮规模。

## 第一轮执行清单

### 启动前

- 确认主要目标、参与范围与交付标准。
- 找到业务伙伴，确认可能的试用场景。
- 检查账号、工具、资料使用范围与咨询入口。
- 与主管和参与者确认时间，明确支持人员。
- 提前对齐评审标准、接受的材料形式与工作量。

### 创作中

- 帮助参与者找问题、伙伴和合适的任务范围。
- 中途看最小可演示版本，及时处理卡点。
- 记录重要调整，向参赛者统一说明。
- 提前检查提交、体验、评审与展示流程。

### 结束后

- 给参与者提供具体的评价理由与改进方向。
- 为准备继续推进的作品明确使用者和负责人。
- 回看个人贡献，安排必要的发展交流。
- 保留模板、卡点与试用记录，用于下一轮调整。

## 交流备用问题

**非技术岗可以参加吗**

可以，已有非技术岗位创作者完成作品的案例。任务范围、工具基础与支持方式，需要结合参与者实际情况安排。

**没有平台可以办吗**

小规模第一轮可从说明页、报名表、作品表和评审表开始。先确保信息能衔接，再增加平台功能。

**请不到高管评委怎么办**

先找了解业务问题、能提供反馈或支持试用的人。邀请时说清需要看哪些材料、投入多少时间，以及作出什么判断。

**非脱产是否就不会影响工作**

仍需讨论投入时间、业务冲突与任务范围。非脱产是一种安排，不能单独证明业务影响很小。

**如何衡量比赛有用**

交付看作品，体验看参与者反馈，应用看持续使用，人才发展看后续行为。不同证据回答不同问题。

## 第一轮筹备参考

以下为结合案例整理的建议，供听众筹备时选用，不作为本项目全部已完成动作的记录。

| 材料 | 需要说明什么 |
|---|---|
| 任务说明 | 为什么办、谁参与、选题方向、作品要求、时间、支持与评价方式 |
| 报名表 | 选题、使用者或体验对象、成员分工、支持需求 |
| 作品提交材料 | 项目说明、体验或演示入口、AI使用过程、已有反馈与当前限制 |
| 初审评估表 | 作品与赛道、评委结论、理由、待澄清问题；独立收集后进入合议 |
| 赛后跟进表 | 创作者与使用者、下一步尝试、负责人和回看时间 |

### 评委需要的材料与问题

今年活动网页的五个评价维度是业务价值、创新性、完成度、可推广性和展示效果。不同赛道结合目标确定侧重，分享不提供未经确认的权重。

提效作品先说明谁遇到什么问题、现有方式有什么不便，再说明作品改变了哪个环节，用什么反馈支持判断。创意作品可以说明希望提供怎样的体验、AI用于哪些环节，以及目前能完整体验什么。两类作品都需要讲清创作者自己的判断和当前限制。

评委先独立填写结论与理由，合议再讨论不同意见。公开点赞反映关注与传播，不直接替代专业评审。

### 中途遇到困难时

参与意愿不高，可以先了解任务是否贴近岗位、时间条件是否具备、起步难度是否合适。作品做不完，先检查范围、工具和卡点，再决定需要哪些支持。如果调整统一规则或截止时间，应向所有参赛者说明。

### 展示前的检查

检查链接、账号、网络、设备和资料脱敏，准备录屏或离线材料备用。若作品需要多人同时访问，提前请技术支持确认使用条件并做访问演练。没有进入路演的创作者，同样需要体验机会和能够理解的反馈。

### 资料与数据说明

作品广场采用实际界面并进行AI辅助脱敏，页面票数只代表截取时的状态；初审增加深入复盘中的实际评委工作台，另保留明确标注的机制示意。滚动形式用于浏览作品广场截图，不冒充原文中的动态图。深入复盘补充了直接费用口径，但完整工时和长期应用效果仍缺依据，不推算完整ROI。

## 深入复盘对本次分享的补充

这份9月3日活动复盘补充了原定方案与实际执行的差别：21天指创作安排，之后还有初审、试玩、路演和收尾；活动网页的5分钟作品介绍与答辩，在实际决赛中按每组8分钟安排。原定命题池没有实际使用，后续SOP中建议的改法也不直接作为本届成果。
